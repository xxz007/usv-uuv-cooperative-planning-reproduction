# 01｜从安全地图到实际路径

本主题先解决“能否在声明的地图规则下找到安全路径”，再检查同一条几何路径如何影响执行。P1使用小型四邻接栅格；X1把四／八邻接接入完整协同案例。两者的尺度和结论范围分别保留。

**地图与搜索规则**

障碍按安全缓冲扩张后形成禁行节点。A*在允许的相邻节点间搜索，返回路径后还要检查起终点、连通性和禁行约束。四邻接每条单位边长度为1；八邻接增加长度为√2的对角边，并检查切角与连续线段安全。节点数减一只适用于单位边路径。

P1保存的小例说明了障碍变化的影响：

| 场景 | A*状态 | 路径长度／单位栅格边 |
|---|---|---:|
| 基准 | found | 6 |
| 增加障碍 | found | 14 |
| 不可达 | unreachable | null |

直线路径长度仍为6不代表直线仍可行。不可达结果保留`null`，不以观察截止时刻或一条违规直线代替路线。

**新运行示例**

```bash
.venv/bin/python -B -m usv_uuc_cooperation.main run --stage P1 --run-id learn_path_01
```

摘要位置：`$PWD/results/p1_pathfinding/runs/learn_path_01/摘要.md`。关注`status`、`astar_length`和返回路径；对照[已保存P1结果](../../results/p1_pathfinding/README.md)。运行环境见[复现说明](../reproduction.md)。

**从局部路径走向完整执行**

X1在同一P4动态案例中得到以下保存结果：

| 邻接规则 | 任务完成 | 六艇全窗实际总航程／m | 团队完成时间／s |
|---|---:|---:|---:|
| 四邻接 | 22/22 | 150.621588069 | 65 |
| 八邻接 | 22/22 | 120.973907199 | 54 |

邻接规则会影响路径成本，也可能改变初始分配、访问顺序和动态接手。此表反映完整系统效果，不能把全部差值只归因于一条局部对角边。

执行器按速度、步长和航点逐步移动；某一步尚未到达航点时，保留当前计划项。几何路线长度、离散到达时刻与完成服务时刻分别记录，避免把“搜索得到路径”直接登记为“任务已完成”。

相关实现见[路径规划模块](../../usv_uuc_cooperation/planning/)；[X1案例入口](../../results/x1_adjacency/README.md)保留完整对照来源。上述安全性限于声明的二维障碍和执行检查，真实船体运动与艇间碰撞另见[适用范围](../scope.md)。
