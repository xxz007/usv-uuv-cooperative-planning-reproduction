# 学习路线

本项目围绕一个问题逐步展开：让1个USV和5个UUV完成二维任务，同时记录路径、通信中继、移动预算及动态事件的影响。这里保留方法、操作与结果之间的联系；逐轮课堂问答和机械验收原件仍在本地课程档案中。

| 阅读顺序 | 解决的问题 | 对应原阶段 |
|---|---|---|
| [01 路径规划](01_path_planning.md) | 怎样把地图、安全缓冲和最短路接到实际移动 | P1、X1 |
| [02 任务分配](02_task_allocation.md) | 怎样区分任务归属、访问顺序和完整路线目标 | P2、P4求解部分、X1 |
| [03 协同执行](03_cooperative_execution.md) | 怎样把任务、服务、中继和移动预算放到同一时间轴 | P3 |
| [04 动态重规划](04_dynamic_replanning.md) | 新任务、洋流和故障到来时，哪些状态可以改、哪些应保留 | P4、X1 |
| [05 算法对比](05_algorithm_comparison.md) | 怎样公平比较六种路径方法并解释差异 | X2 |
| [06 MOOS与VRX](06_moos_vrx.md) | 怎样从目标下发走到平台反馈与同任务对照 | P5 |

P0的环境和模型约定归入[复现说明](../reproduction.md)与[适用范围](../scope.md)。P6的版本、干净副本复跑与恢复交付也集中在复现说明中，不另设一套重复的学习目录。P0～P6、X1、X2主线已经结束；后续研究建议与已完成结果分别登记。

建议先运行P1小例，再阅读P2的分配反例；理解P3的成功与受限失败后，再进入P4动态案例和X2方法比较。MOOS／VRX需要各自的平台环境，可以先阅读其保存结果。

**阅读与运行约定**

- 文中的结果表来自已保存且已核对的运行；整理这些笔记没有重做全部实验。
- 代码块是新运行示例，从仓库根目录执行；先按复现说明准备`.venv`，求解部分另用`.venv-solver`。
- 每次使用新的运行名，程序拒绝覆盖已有目录。`$PWD/results/...`在执行时展开为当前仓库内的绝对输出位置。
- 原本人操作、教师机械核查与目录迁移后的工程复跑分别记录；示例命令、目录存在或检查PASS都不自动形成新的本人学习证据。
- 读一个案例时先看完成数、实际总航程或NEU、团队完成时间，再按需要追到原始数据。

统一的[结果表](../results.md)用于比较，具体图与数据从各案例入口进入。二维通信与移动NEU的物理含义、单艇平台验证范围和未完成的研究机制见[适用范围](../scope.md)。
