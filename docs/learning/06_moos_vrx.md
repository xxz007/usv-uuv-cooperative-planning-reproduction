# 06｜从目标发布到平台反馈

P5验证两个独立平台入口：MOOS中的单艇任务接口，以及ROS／Gazebo中单艘WAM-V的VRX原例和同任务对照。平台动作、观测与任务完成反馈形成记录，二维协同案例没有被整体迁入多艇平台。

**MOOS：怎样判断任务确实完成**

任务包含自己的ID和目标；执行端回传实际NAV与该任务的完成事件。仅“目标发布成功”只能证明发送动作，登记完成还要看到同一任务的完成反馈，并确认实际位置已进入到达范围。

本人保存的MOOS主任务完成1/1，派发至完成19.08模拟秒。短反馈窗保留TIMEOUT，非法目标在发送前REJECTED；两种失败均没有误报完成。当前是单艇uSimMarineV22，不能据此宣称1USV＋5UUV的MOOS平台闭环已经完成。

主环境可先查看入口；实际运行还需独立编译的MOOS-IvP：

```bash
.venv/bin/python -B -m usv_uuc_cooperation.experiments.p5_moos --help
```

此命令仅显示帮助，不产生任务结果。实际启动命令、外部依赖和绝对输出位置以[复现说明](../reproduction.md)为准；[P5结果入口](../../results/p5_platforms/README.md)可以直接查看保存数据。

**VRX：先确认原例，再做同任务对照**

保存的原例使用官方完整艇体：左右各100N、约8模拟秒内实际水平位移6.093563m，并收到1280×720 RGB8相机帧。位姿保留原生实体名称和ID；完整艇体的质量、惯量、动力学和传感器保持，真值对照仅增加原生里程计插件。

本人同任务对照使用共同实测起点／朝向、前方20m目标、标称速度1.5m/s、到达半径2.5m、连续有效采样保持1s和90模拟秒预算：

| 系统 | 完成时间／模拟秒 | 最大横向偏差／m | 预定义包络违规事件 |
|---|---:|---:|---:|
| VRX完整WAM-V | 15.7 | 0.008682373 | 0 |
| 独立理想二维 | 12.7 | 约0 | 0 |

标称速度不等于平台的瞬时实际速度；理想二维省略推进响应、惯性和水动力等因素，因此同任务完成时间可能不同。本次两系统均完成，差异限定于这个任务，不形成算法普遍优劣结论。

**保留平台之间的边界**

MOOS、VRX原例和VRX同任务配对分别启动、运行和保存，不拼接成连续多平台协同轨迹。采样坐标未越出包络不证明连续避障或艇间避碰安全；推力发布也不等于实测推进功率。

已保存的VRX环境为Ubuntu24.04、ROS2 Jazzy、Gazebo Harmonic，使用Linux系统Python3.12；它与本项目二维算法的Python3.13虚拟环境分别准备。原本人操作／解释和教师机械检查已有证据，整理笔记没有重新执行平台仿真。

当前结果属于平台仿真，尚无水下六自由度载体、水上水下多艇集成、真实水声链路或实艇验证。完整完成范围与后续缺项见[适用范围](../scope.md)。
