# 03｜把任务、服务、中继和预算接到同一时间轴

P3把规划结果放入1USV＋5UUV＋20任务的二维执行器。任务需要经过实际移动、到达和服务后才完成；USV的中继移动与UUV的任务移动同步记录，结果来自连续执行日志。

**共同规则**

固定地图、seed20261008、容量4和观察窗[0,120)。通信使用USV到各UUV的水平距离阈值；移动NEU按系数乘实际位移累计。服务、等待和理想驻留的能耗假设独立说明，不把NEU解释为电池实测。

主案例使用失联优先中继。质心中继也有P4-L1 G3的正式执行证据，但它与P3主动画不是同一策略组；阅读图时应核对其运行来源。

| 同一基线案例 | 完成任务 | 团队完成时间／s | 六艇全窗移动NEU | 通信保持率 |
|---|---:|---:|---:|---:|
| SUCCESS | 20/20 | 48 | 380 | 9.33% |
| RESTRICTED | 16/20 | null | 314 | 5.83% |

RESTRICTED仅把U3移动预算改为12NEU。120s是观察截止，未完成的团队时间保留`null`；314小于380不能说明完成同样任务更节能。SUCCESS任务全完成但通信保持率仍低，任务成功与通信质量是不同指标。

**新运行示例**

```bash
.venv/bin/python -B -m usv_uuc_cooperation.main run --stage P3 --case ALL --run-id learn_cooperation_01
```

摘要位置：`$PWD/results/p3_baseline/runs/learn_cooperation_01/摘要.md`。先读完成数、成功时间和NEU，再追查某艇预算、任务状态及失联区间。已有[成功与受限失败结果](../../results/p3_baseline/README.md)可直接阅读，无需为了查看动画重跑模拟。

**执行与解释中的关键点**

计划中的任务归属不等于任务已完成，航点到达也不等于服务已经结束。实际位移、服务进度、任务完成时刻与失败原因分别保存。

通信配置当前承担评价作用，距离阈值之外的失联不会自动触发水声传播、MAC或网络路由过程，也不能据此推断通信硬约束已经满足。中继策略采用确定性规则；一个受限案例失败不证明所有可能策略都不可行。
